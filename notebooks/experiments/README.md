## 進め方

**1つの Notebook で1つの工夫に絞る。**
複数まとめて試すと、点数が動いたときにどれが効いたのか分からなくなる。

**比べ方を tutorial と揃える。**
`tutorial/04_model.ipynb` と同じ分け方（`test_size=0.2, random_state=0, stratify=y`）で
採点すれば、工夫の前後を直接比べられる。条件を変えると比較にならない。

**1回の数字を信じない。**
採点相手が変わるだけで AUC は 0.76〜0.92 まで動く。
数ポイントの差は偶然の範囲なので、分け方を何通りか変えて平均で比べる。

**投稿は1日5回まで。**
手元で良くなったものだけ投稿する。Public の点数を見ながら調整すると、
評価用データの一部にだけ都合の良いモデルになる（`tutorial/05` 参照）。

## 各 Notebook に書き残すこと

- **何を試すか**（仮説）
- **なぜ効きそうか** — `tutorial/` のどの結果を根拠にしているか
- **手元での点数** — 工夫の前後を並べる
- **効いたか / 効かなかったか**、そしてその理由の見当

**効かなかった検証も消さない。** 何が駄目だったかは、
次に何を試すかを決めるための材料になる。上の表にも残す。

## 試す候補

`tutorial/05_submit.ipynb` のまとめで挙がったもの。

**1. `age` を子ども／大人で区切る**

02 の相関係数では -0.081 と弱く見えたのに、04 のモデルでは3番目に効いていた。
相関係数は「一方向に増えるほど増える」関係しか捉えられないので、
「子どもは助かり、大人は助からない」という関係を見落とす。
そのまま使うのではなく区切りを入れると伸びる可能性がある。

**2. 空いている場所を学習用だけの値で埋める**

03 では学習用と評価用を繋げた状態で平均を求めている。
**本当は知らないはずの評価用データの様子**を使って加工していることになる。
学習用だけから求めた値で両方を埋める方が正しい。

**3. 条件の組み合わせを扱える仕組みを試す**

ロジスティック回帰は「項目ごとに重みを掛けて足す」だけなので、
「3等でも女性で子連れなら助かりやすい」といった組み合わせを表現できない。

ただし 04 で見たとおり、表現力が高い仕組みは覚え込みすぎる危険がある。
決定木を制限なしで使うと、学習用 0.99 / 検証用 0.72 まで開いた。

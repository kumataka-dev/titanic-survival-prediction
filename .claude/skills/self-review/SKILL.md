# セルフレビュー

コミット・PR 作成の前に行う自己点検。**目的はレビュアーの負担を減らすこと。**
常に報告専用で、修正は行わない。直すかどうか・どう直すかはユーザーが判断する。

```
- [ ] 1. 対象と effort の確定
- [ ] 2. 渡す規約ファイルの収集
- [ ] 3. code-review の実行
- [ ] 4. 指摘の検証
- [ ] 5. 報告  ← 修正は行わない
```

## 1. 対象と effort の確定

`args` は **effort（省略可）→ 比較対象のブランチ名（省略可）** の順で受け取る。

| 位置 | 内容 | 例 |
| --- | --- | --- |
| 1つ目 | effort（`low` / `medium` / `high` / `xhigh` / `max`。省略可、既定は `low`） | `low` |
| 2つ目 | 比較対象のブランチ名（省略可） | `develop` |

`code-review` の effort は「探索範囲 ↔ 確信度」のトレードオフ。

| 値 | 意味 |
| --- | --- |
| `low` | 最も確信度の高い指摘のみ。誤検知（false positive）が少ない |
| `medium` | `low` よりわずかに広いが、引き続き高確信度の指摘を優先する |
| `high` | 対象範囲を広げる。確信度がやや低い指摘も含まれ始める |
| `xhigh` | `high` よりさらに広く・長く探索する（長時間の作業向け） |
| `max` | 最大範囲まで探索する。トークン消費に制約を設けない分、確信度の低い指摘も多く含まれる |

**対象の決め方**（自分で解決する。呼び出し元はブランチ名だけ渡せばよい）:

- **省略された場合（既定）**: `git diff --staged` を見る。ステージが空なら `git diff`（作業ツリーの
  未コミット変更全体）にフォールバックする
- **ブランチ名が指定された場合**: `git fetch --prune origin` した上で、`origin/<ブランチ名>...HEAD`
  の差分を見る（現在のブランチと指定ブランチの共通の祖先からの差分。`origin/` を付ける・fetch する・
  3点リーダー記法にする、はすべて自分で行う）
- **呼び出し元が対象そのものを渡してきた場合**: それをそのまま使う。勝手に広げない

引数が省略された場合は `effort=low`・対象は上記の既定として扱い、その前提を最初にユーザーへ伝えてから進める。

## 3. code-review の実行

`Skill` ツールで `code-review` を呼ぶ。`args` は **effort → 対象 → 追加のレビュー観点** の順。

```
skill: code-review
args:  <effort> <解決した対象> を対象にレビューする。
       加えて <手順2で収集した規約ファイル> の「レビュー時のチェック項目」を
       追加のレビュー観点として適用すること。
       報告してほしいのは <手順2で挙げた観点> のみ。
       「記載された事実の誤り」は必ず実測して判断すること。
       `ReportFindings` は探さない（フォークされるので使えない）。findings は JSON 配列で返す。
```

## 4. 指摘の検証

`code-review` の指摘それぞれについて、**該当箇所を実際に開いて**指摘の前提が事実と合っているか検証する。
事実と異なる指摘は却下し、理由を残す。

他のエージェントの報告を鵜呑みにしない。存在しない行・実際には通らない経路を前提にした指摘は珍しくない。

## 5. 報告

指摘には次の3段階の深刻度を付ける。

| 深刻度 | 意味 | 該当する指摘 |
| --- | --- | --- |
| **必須** | 直すべきもの | バグ／セキュリティ・機密情報の混入／記載された事実の誤り |
| **推奨** | 直した方がよいもの | 規約ファイルに基づく指摘／スコープからの逸脱 |
| **提案** | こうした方がよい、という改善案 | 上記に当てはまらない改善の余地 |

指摘が1件以上あるときは、**まず一覧表（`#`／深刻度／箇所／一行）で件数と全体像を示し、
そのあとに各指摘の詳細を書く。**

- 各指摘は結論（いつ・何が起きるか）から書く。抽象的な見出しだけで済ませない
- 該当箇所の実物（行番号付きで引用）と指摘を対応させて示す。要約した引用は使わない
- 却下した指摘も、理由とともに報告する

指摘が0件なら、その旨と、何を見た上で0件だったのか（対象・effort・適用した観点）を報告する。

---

## やらないこと

- **修正しない。** 報告専用。直すかどうかはユーザーが決める
- **コミット・push しない。** 履歴を触らない
- 対象範囲を勝手に広げない。呼び出し元が対象を指定した場合はそれに従う
